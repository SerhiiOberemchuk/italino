# Тижневий цикл доставки Італія → Україна

Це логістична модель, навколо якої побудовано сайт. Усе нижче **підтверджено
власником**: відправка щонеділі (2026-09-17); дедлайн середа 16:00, отримання
в середу–четвер і безкоштовна доставка від 5 000 ₴ (2026-09-21).

## Цикл одного тижня

| Момент | Подія | Що бачить покупець |
| --- | --- | --- |
| Ср 16:00 (мин. тижня) – Ср 16:00 | Прийом замовлень у поточну поставку | Банер «Наступна відправка — нд, DD місяця. Замовляйте до середи 16:00» + зворотний відлік |
| Ср 16:00 | **Дедлайн (cutoff).** Замовлення після нього потрапляють у наступну поставку | Банер перемикається на наступну неділю |
| Чт–Сб | Комплектація в Мілані | Статус «Комплектуємо» |
| **Нд** | **Відправка з Мілана** | Статус «Відправлено», лист/повідомлення |
| Нд + 2 дні | Прибуття в Україну, митне оформлення, передача в Нову Пошту | З'являється ТТН |
| + 1–2 дні | Доставка у відділення чи поштомат | Статус «У відділенні» → «Отримано» |

Від відправки до отримання — **3–4 дні**: виїхало в неділю — у клієнта в
середу–четвер. Від дедлайну до отримання — ≈ 7–8 днів; найдовше чекає той, хто
замовив одразу після дедлайну, — до двох тижнів.

## Розклад у коді

Розклад описано одним об'єктом у `src/lib/shipping/schedule.ts`:

```ts
export const SHIPPING_SCHEDULE = {
  timeZone: "Europe/Kyiv",
  cutoff: { weekday: 3, hour: 16, minute: 0 }, // середа 16:00
  dispatchWeekday: 0,                          // неділя
  borderDays: 2,                               // до передачі в Нову Пошту
  lastMileDays: { min: 1, max: 2 },            // Нова Пошта до відділення
};
// TRANSIT_DAYS = borderDays + lastMileDays → 3–4 дні
```

Функції `nextCutoff()`, `nextDispatch()`, `estimatedArrival()` рахують дати з
урахуванням часового поясу Києва.

**Тексти про графік руками не пишемо.** Усі фрази («до середи 16:00»,
«щонеділі», «3–4 дні», «у середу–четвер», «Ср, 16:00»…) беруться з
`SCHEDULE_COPY` у тому ж файлі. 20.09.2026 дедлайн змінили лише у футері, і сайт
кілька днів показував два різні графіки — включно з таймером і приміткою до
кожного замовлення в CRM. Зміна константи тепер оновлює смугу оголошень, банер
і «Як це працює» на головній, футер, сторінки доставки й товару разом.

## Безкоштовна доставка

Від порогу (власник: **5 000 ₴**, межа включна) доставку Новою Поштою оплачує
продавець. Поріг задається в Obriym CRM і приходить у `GET /capabilities` як
`cart.freeShippingThreshold`, тож кампанію можна запустити без релізу сайту.
Вітрина його не дублює:

- серверні сторінки (доставка, оферта, «Оплата», товар, «Чому Italino» на
  головній) беруть його через `getFreeShippingThreshold()`;
- кошик і чекаут отримують його пропсом;
- правило — `qualifiesForFreeShipping()` у `src/lib/shipping/free-shipping.ts`,
  та сама включна межа, що й у CRM.

`null` (поріг не задано або CRM недоступна) — безкоштовну доставку не обіцяємо
ніде, включно з офертою. Значення кешується разом із capabilities (близько
хвилини); оновити негайно — `POST /api/revalidate` з тегом `capabilities`.

CRM сама поріг до накладних не застосовує: автоТТН бере одного платника на
весь workspace. Тому чекаут дописує в примітку замовлення «БЕЗКОШТОВНА
ДОСТАВКА … ТТН оформити за рахунок відправника».

## Статуси замовлення

Публічний API Obriym CRM повертає статус замовлення з фіксованого списку.
Сайт показує покупцю **свої** формулювання:

| Статус у CRM | На сайті | Коли |
| --- | --- | --- |
| `pending` | Прийнято, очікує підтвердження | одразу після checkout |
| `confirmed` | Підтверджено, у поставці від DD.MM | менеджер підтвердив; оплата отримана або обрано накладений платіж |
| `processing` | Комплектуємо в Італії | після дедлайну |
| `shipped` | Відправлено з Італії / В Україні (коли є ТТН) | день відправки; ТТН з'являється після прибуття |
| `delivered` | Отримано | НП підтвердила вручення |
| `cancelled` | Скасовано | за запитом покупця або якщо речі немає в наявності |
| `refunded` | Повернено кошти | після повернення |

ТТН і трекінг беруться з `GET /api/v1/orders/{externalId}/shipments`
(`carrier: "nova_poshta"`, `trackingNumber`).

## Крайові випадки

- **Замовлення після дедлайну.** На checkout показуємо явно: «Це замовлення
  поїде поставкою від DD.MM (наступна неділя)».
- **Речі немає в наявності в Італії.** Менеджер скасовує позицію в CRM
  (`PATCH /orders/{externalId}/items/{itemId}` або скасування замовлення);
  покупець отримує повідомлення і повернення передоплати.
- **Святковий тиждень / пропуск відправки.** Тимчасово — зміна константи
  розкладу; цільове рішення — розклад у CRM.
- **Обмін розміру.** Повернення приймається в Україні, обмін їде з наступною
  поставкою. Політика 14 днів — припущення.

## Комунікація з покупцем

Кожна зміна статусу — повідомлення на e-mail (і, за бажанням, Telegram):
підтвердження замовлення з датою відправки → відправлено з Італії → ТТН
Нової Пошти → отримано (запит відгуку). Реалізація сповіщень — на боці CRM
(webhook або server function); сайт лише показує стан.
